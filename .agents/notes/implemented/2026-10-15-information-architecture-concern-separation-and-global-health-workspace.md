# Agent Note: 信息架构关注点解耦与全局渠道健康工作台

Status: implemented

## Problem

在 Master-Detail 布局初步落地后，控制台暴露出深层的“关注点混叠”（Conflation of Concerns）结构性病症：
1. **配置意图 vs 运行时观测混在同一层**：
   - 用户打开任意一条规则，迎面是「降级流水线」、「异常策略与预算」和「渠道遥测与监控」3 个并列子 tab。
   - 观测数据（24 柱时间条、tok/s、健康历史）直接霸占了配置界面，破坏了声明式配置的心智聚焦。
2. **健康检测维度错位**：
   - 底层 `channelHealthProjection` 和发现接口均以物理渠道（`provider/model`）为唯一键。
   - 在规则链路维度展示健康监控，会导致同一个渠道在多个 profile 中重复渲染，且曾经观测过但已被移出规则的渠道完全失去观测入口（产生盲区）。
3. **顶栏全局诊断操作越权**：
   - 「检查全部渠道」、「健康监控设置」、「故障转移历史」三个全局运行时动作摆在模态顶栏，与「保存配置」并列，使用户误以为它们是属于当前规则配置文件的动作。
   - 双引擎（连通性检查 vs 真实测速探测）动作语义模糊、成本不透明。

## Decision

1. **左侧导航与信息架构彻底解耦**：
   - 导航栏采用 `[搜索 + "+"] -> [🌐 全局默认兜底] -> [模型规则列表] -> [── 分隔线 ──] -> [📊 渠道健康监控]` 的目标 IA 结构。
   - 全局渠道健康入口独立常驻底部，聚合徽标展示全渠道最差状态与渠道总数。
2. **规则模式纯净化与信号灯联动**：
   - 规则视图子 Tab 收敛为纯粹的配置两档：`['pipeline', 'policies']`，彻底移除规则内的遥测面板。
   - 流水线候选行内仅保留极简呼吸信号灯（`HealthSignalDot`），悬浮展示可用率与延迟，点击直接阻断冒泡并联动跳转至全局渠道健康页，并自动聚焦滚动至对应物理渠道卡片（`focusRoute`）。
3. **全局渠道健康与遥测工作台落地 (`GlobalHealthWorkspace`)**：
   - 以物理渠道（`provider/model`）单例聚合呈现所有规则、默认池及历史留痕的渠道。
   - 提供 4 档快捷筛选（全部 / 正常 / 异常 / 未调用）与即时搜索。
   - 顶栏全局诊断工具完全内嵌于渠道健康页头部，明确标注成本与范围（如 `刷新连通性 · 0 Token`）。
   - 行内提供连通性检查（0 Token）；**测速档（1 Token）只作说明、禁掉按钮**——手写单文件没有构建管线，生成不了 Typert 远程贡献，从浏览器触发不了真探测。可点却只弹提示的按钮和"保存了但没存上"是同一种谎言，处理与 `HealthSettingsModal` 里那一档保持一致（禁用 + 原因说明）。
4. **顶栏彻底脱水**：
   - 顶部主操作栏（页面粘滞顶栏与模态顶栏）只保留配置生命周期动作（全局开关、未保存提示、放弃修改、保存草稿），不再承载与配置无关的诊断操作。
5. **健康状态单源派生 (`routeStatus`)**：
   - 信号灯、导航徽标、全局筛选与渠道卡片原来各自内联一份 `passive ? ... : discover ? ... : unknown` 表达式（五处），既会漂移，也让同一处语义错误被复制五份。
   - 收敛为模块级纯函数 `routeStatus(passive, discover, route)`：真实观测优先于连通性判定；**连通性检查跑不了（发现接口不可用 / provider 不可配置）读作 `unknown`，不是故障**——旧 `HealthDots` 本来就是这么映射的，全局工作台一度改成了 `unhealthy`，把"问不出端点"显示成红色"异常"且无法消除，已随单源化修正。

## Consequences

- 收益：
  - 彻底根治关注点混叠病症，配置归配置（纯粹意图表达），观测归观测（全局物理网格）；
  - 观测数据全域去重，无死角覆盖所有在编和历史物理渠道；
  - 诊断操作位置对齐、成本透明，点击候选信号灯一秒直达全局详情。
- 代价：
  - 规则视图不再直接展示被动观测细节，看详情需一次跳转；
  - 测速档在构建管线就绪前只能看不能用（模态与工作区均为禁用 + 说明）。
- 验证：
  - `node --check packages/dsh-model-router/src/client.js`：通过；
  - `node packages/dsh-model-router/tests/client-controller.mjs`：20/20 通过（含 `routeStatus` 映射、单渠道检查与工作台结构回归测试）；
  - `node packages/dsh-model-router/tests/unit.mjs`：35/35 通过；
  - `node packages/dsh-model-router/tests/run.mjs`：12/12 真实 Loader 组合测试通过；
  - `tsc --noEmit`：0 错误；
  - 隔离 `.dshhome-view` 浏览器实测：双栏布局、信号灯跳转聚焦、导航进入清除焦点、单渠道连通性（unavailable 显示"未调用"）、测速禁用、搜索图标定位、dirty→保存闭环；
  - DSH 源码树（`D:\sudy\github\deepseek-harness`）：严格 0 修改。

## 实施事故：少一个右括号把工作区嵌进侧栏

重构中途一度出现"整个页面只有左侧可用"：DOM 实测 `#panel-global-health` 的父元素是 `aside` 而不是 workbench——侧栏 `h('aside'` 少闭一个括号，`isHealthMode` 工作区 div 落成了侧栏的第三个孩子，被压进 260px 列。**括号总数配平、`node --check` 通过**，结尾多收的一个括号把账补上了，所以是静默的结构错位。修法：侧栏闭合补回导航项之后、工作区三元之前（收尾层级减一），并新增结构回归测试 `the workbench keeps the sidebar and the workspace pane as siblings`——从侧栏开括行走深度，要求其在 `isHealthMode` 之前闭合；对"配平但错位"的原始形态精确报红。教训与 tools.md 既有记载一致：手写 createElement 深嵌套，配平不等于结构。
