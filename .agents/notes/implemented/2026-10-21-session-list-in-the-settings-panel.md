# Agent Note: 设置面板里的会话清单（按会话直接配）

Status: implemented

## Context

第一批的入口只有 composer 里的 chip：会话选链、每个候选的重试次数。用户上手后的第一句话是
"我不应该选择会话吗？怎么手动输入？你这是先配置再选是吧？……插件 UI 可以看所有的可配置，输入框
这个配置当前的也可以啊"。也就是说：**他要一个能列出所有会话、直接给某个会话配链的地方**，chip
配当前会话是认可的，但不能是唯一入口。

约束来自 DSH 本身：设置面是全局的，插件拿不到"现在前台是哪个会话"（`docs/design/per-session-chains.md`
二.1）。所以面板不能靠"当前会话"这个输入，只能列出来让用户挑。

## Decision

1. 链路页多一个页签「会话路由」：列出会话 × 各自的绑定，按 `updatedAt` 倒序，最多 20 条
   （与健康页读投影的上限同量级）。
2. 数据来自两个已有读口：`routerHealth.sessionBindings()`（新增：全部绑定一次读回）与
   `remote.session.list({})`；标题走 title 投影（与健康页同一条读法），读不到就显示 id 末 8 位。
   两侧都有的行可以改；只在绑定里的行是被删掉的会话，只提供「清除绑定」。
3. 行内直接配：链用原生 `<select>`（选项 = 跟随默认链 + 每条链），下面是该链候选的重试行，
   **空 = 跟随链、0 = 不重试**，与 chip 共用 `parseRetryInput`（一个判断，两处使用）。
4. 写入仍走 `setSessionBinding`（整份 `{ chain, retries }`），成功才更新那一行；失败把宿主原样
   抛出的错误显示在分区里，行保持原值。
5. 新增 `deleteSessionBinding`（幂等）：被删会话的绑定由用户手动清，不加后台任务。
6. **chip 与这一页写同一份侧车**，所以两边永远一致；chip 是"当前这个会话"的快捷入口，
   面板是"所有会话"的总览。
7. 只在打开页签时读（`setActive('__sessions__')`）与手动「重新读取」，不做订阅：会话列表是
   低频数据，推它等于每开一次会话推一次。

## Alternatives considered

1. **只保留 chip（不改面板）。**
   - 最强的理由：一个入口，一个真相；用户看到的配置永远是他正在聊的那个会话。
   - 为何被否：用户明确要求"选会话去配置"。给三五个会话分别设链，必须逐个进会话点 chip，
     而他当时正想在一个地方看全貌。
2. **面板里放"当前会话"的快捷方式（读 DSH 的选择状态）。**
   - 最强的理由：与 chip 完全等价，用户不用找。
   - 为何被否：DSH 不暴露"前台会话"，选择状态是 session-controller 私有字段；猜一个就等于
     给用户看错的那个会话。
3. **把会话清单做成一个弹窗（从 chip 或按钮打开）。**
   - 最强的理由：不占页面的常驻空间。
   - 为何被否：会话列表是"看看还有谁配过"的总览，弹窗一关就没了；页签与链、健康并列更自然。
4. **面板里只显示绑定过的会话（不列 `session.list`）。**
   - 最强的理由：零会话列表读取、零标题投影，一个读口就够。
   - 为何被否：用户要的是"选一个会话去配"，未绑定的会话恰恰是主要目标；只列已绑定的等于
     只能改、不能选。
5. **保留"被删会话"的绑定不展示。**
   - 最强的理由：界面上少一类难解释的行。
   - 为何被否：这些记录会永远留在侧车里，占空间且让"清空重来"做不到；虚线边 + 「清除绑定」
     一行就说清楚了它是什么。

## Consequences

- 收益：不用进会话就能把几个会话各自指定到不同链；被删会话留下的绑定有一个明确的清理入口。
- 收益：`sessionBindings` / `deleteSessionBinding` 让"全部绑定"与"对账"都变成一次读、一次写，
  不需要为列表逐会话发请求。
- 代价：多两个 Remote 与一个页签；会话很多时列表被截到 20 条（更早的会话要进聊天用 chip 配）。
- 代价：标题要逐会话读 title 投影（20 次本地读），读失败时只显示 id 末 8 位——这是有意的
  降级，不阻塞绑定编辑。
- 代价：**"跟随默认链"的会话行显示的是默认链的候选**。第一版没做这一步，用户会看到一行
  没有任何重试行、以为这个会话不能配（浏览器实测当场抓到，已修）。
- 未做：绑定到"已删除的链"的行在面板里只按"跟随默认"显示候选；那条 notice 仍在请求时发出。
