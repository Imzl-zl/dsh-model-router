# AUTH 与 QUOTA 纳入 switchOn（密钥失效也切换）

Status: implemented

## Problem

2026-10-16 用户提问戳中一个产品级缺口：「密钥失效肯定也是需要切换的啊，做这个不就是各种问题
自动切换吗？」

原设计（open-questions 一.5、product-plan §2.2）把 `AUTH`/`QUOTA` 与 `ABORTED`/`NO_ADAPTER`
一起列为"明确不切换"，理由是"要么是用户主动中断，要么是配置坏了，切换只会把问题藏起来"。

实测该理由在本插件里不成立，两条：

1. **熔断本来就会绕过死渠道**。`breaker.note()` 在失败当时就记录（`agent/request-error` 监听里，
   早于任何 recovery 决定），所以密钥失效后**下一个请求**就会跳过这条渠道、直接走备用。也就是
   说系统早已决定"绕着死密钥走"——旧设计只是把**第一次请求**也白白搭进去：那次请求硬失败，
   用户/agent 什么也没得到。
2. **切换从不是静默的**。每次切换追加一条中文 notice，点名失败渠道与码（「主模型 X 失败（凭证或
   权限被拒），已切换至 Y（候选 2/2）」），并留下 `request/header` 的 `reason:'change'` 轨迹。
   这比一个干巴巴的终态错误**更响**，不满足"把问题藏起来"。

对 agent/工作流，"带提示的成功"严格优于硬失败：一次密钥失效不该让整轮任务中断，而通知与熔断
保证了可见性与后续规避。

## Decision

- `switchOn` 增加 `auth` 与 `quota` 两个键，**默认开**（与 rateLimit/server/timeout/transport
  一致）。`switchOnKeyOf` 增加 `AUTH → auth`、`QUOTA → quota` 映射。
- 老配置自动获得新默认值：schemastery 的 `.default(true)` 对缺键生效（现有六个键就是这样从
  `switchOn: {}` 得到默认值的），所以无需迁移、也不写兼容分支。
- `ABORTED` 与 `NO_ADAPTER` **仍然不切换**，但理由换成了站得住的那些：
  - `ABORTED` 是用户自己按的停止，`decideRecovery` 开头就返回 terminal（`signal.aborted`）；
  - `NO_ADAPTER` 对**候选**会在调用前被 `resolveCallConfig` 预校验拦掉（抛错即跳过，0 次真实
    调用），对**用户自己的路由**则意味着链上无人能服务，切换没有对象。
- 文案同步：设置页「零浪费熔断安全机制」说明框原先把 AUTH 列为"绝不盲目转移"，已改为只有
  ABORTED/NO_ADAPTER 属于永久性不转移，AUTH/QUOTA 默认切换并说明原因。

## Alternatives considered

1. **保持不切换，只把熔断冷却设短**
   最强理由：密钥失效是配置错误，应当由用户修；切换让坏配置"看起来能用"。
   否决理由：熔断已经在做"绕过"这件事，区别只在他是否让第一次请求失败——而失败的那次对 agent
   工作流是纯损失。且"看起来能用"恰好是插件的产品语义（透明故障转移），可见性由 notice 与
   `request/header` 轨迹保证，不靠失败本身。
2. **AUTH 可勾选但默认关**
   最强理由：不给老用户改变行为，尊重"配置错误应当暴露"的保守立场。
   否决理由：默认关意味着大多数用户永远享受不到这个救场，而它正是本插件最典型的场景之一
   （一个网关渠道密钥失效，另一个渠道有密钥）。产品定位是"自动切换"，默认行为要配得上定位。
3. **把 NO_ADAPTER 也加进来**
   最强理由：同属"渠道自己的毛病"，另一个渠道可能有适配器。
   否决理由：候选侧已被预校验拦掉（加了这个键也无场景可走），用户自选路由侧则是链上无人能
   服务——切换没有对象。加一个不可达的键只会让策略矩阵里多一个骗人的开关。

## Consequences

- 收益：密钥失效/额度用尽从"整轮硬失败"变成"一次切换 + 中文通知 + 熔断避开"，与 RATE_LIMIT
  等瞬时故障同一套体验；老配置零迁移获得新行为。
- 代价：① 主渠道密钥长期失效时，请求会持续走备用（这正是设计目标，但用户可能拖着不修——
  缓解是每条通知都点名死渠道 + 熔断冷却到点后会真打一次再封，成本有界）；② 策略矩阵多两个
  开关，「零浪费熔断安全机制」的文案必须同步改（已改），否则 UI 会说反话。

## 验收（已实跑，2026-10-16）

- 组合 18/18：新增 `auth-dead-key-fails-over`——primary 打 AUTH，durable 日志显示
  headers = [primary, backup]、通知含「凭证或权限被拒」与「已切换至」、turn 正常 completed。
- 单测 87/87：新增 `switchOnKeyOf` 映射（AUTH/QUOTA → auth/quota，ABORTED/NO_ADAPTER →
  undefined）。
- 熔断"跳过死渠道"的行为由既有 `CircuitBreaker` 单测覆盖；组合 harness 一次 boot 只有一个
  step（tools.md 记过的坑），跨请求不可观测，故不在组合层断言。
