# Agent Note: 命名链与会话内 chip

Status: implemented

## Context

用户要"不同会话承担不同任务，需要不同的模型与降级顺序"。2026-10-19 的决定把产品收成
**一条全局降级链**，它否掉的是"为每个模型各配一条规则"，没有否掉"按会话在少数几条链之间
选"。这一批把后者做出来。

两条核过的事实决定了形状：

- DSH 有会话级 UI 槽位，**没有会话级配置**，也不能把状态写进会话日志。所以"这个会话用哪条
  链"只能存在插件自己的侧车（`ctx.storageDomain`，见
  `.agents/notes/implemented/2026-10-21-per-session-bindings.md`）。
- schemastery 给**任何 array schema** 盖上默认值 `[]`（schemastery `src/index.ts:914-918`），
  所以"配置里没写过 `chains`"与"写了一个空列表"在取值上不可区分。判断新旧形状不能靠
  "键在不在"。

原计划把 `chains[] + defaultChainId` 放在第 3 步，但第 2 步的验收是"切换链后下一次请求的
`request/header` 真的换了候选"——只有一条链时没有可切换对象。用户裁定：把配置形状与迁移提到
第 2 步，第 3 步只做重试覆盖行与链管理界面。

## Decision

1. **配置形状**：`chains: NamedChain[]`（每条链 = 原有整套字段 + `id` + `name`）+
   `defaultChainId`。旧的 `chain` 键留在 schema 里只为读取：一旦 `chains` 非空，它不再参与
   任何决定。
2. **迁移**：非空 `chains` 赢；否则按**原始配置里存在的键**读旧形状（`chain` → `profiles` → `default`），折成**一条**
   `id: 'default'`、`name: ''` 的链。行为等价，因为第一跳（用户当前选中的模型）本来就不在
   配置里。
3. **形状判据只看原始配置**（2026-10-21 修正，见
   `.agents/notes/implemented/2026-10-21-raw-config-shape-and-domain-lifecycle.md`）：这一版最初
   用"`chains` 非空"来推断形状，但 schemastery 会盖章，真实旧配置因此读不出旧键——用户现场
   （只有 `profiles`）升级后插件静默不接管。现在 Host 传 `ctx.fiber._config`，键存在与否是事实；
   显式 `chains: []` 按"一条空链"归一。
4. **链名留空 = 默认链**，由字典显示。迁移不把"默认链"这三个中文字写进 YAML：英文界面会
   显示中文，而且会让人以为名字是必填。
5. **会话绑定怎么生效**：`chainForSession` 一处回答"本会话走哪条链"——绑定存在且链存在就用
   它；否则用默认链，并把缺失的 id 报出来，宿主在 `agent/request` 里留一条中文 notice。
   会话保留原绑定：用户重建同名链即恢复，静默改成"没绑定"会把一次删除变成一次改道。
6. **写入阶段拒绝未知链 id**：`setSessionBinding` 只接受配置里存在的链。存下一个永远不生效
   的选择，比当场拒绝更糟。
7. **设置面板同批改成"编辑默认链"**：草稿里是 `{ chains, defaultChainId }`，五个编辑区只改
   `chains[defaultChainId]`；保存写 `chains` + `defaultChainId`，并 `unset` 旧的 `chain` 键
   （首次保存后存储里只剩一种形状）。发布给视图的快照里附一个派生的 `chain` 别名，视图因此
   不必知道"当前编辑的是哪一条"；draft 上没有这个键，脏检查比较的也是有它的那一份。
8. **结构规则按链逐条跑**：重复路由、权重策略只按**同一条链内**判（两条链可以合法地共用一条
   渠道——它们是不同任务的备胎顺序）；新增两条：链 id 重复、`defaultChainId` 指向不存在的链。
   问题文案带"第 N 条链"，因为现在不止一条。
9. **chip 挂在 `conversation.input.left`**：它是 composer 工具行的会话级 list 槽，渲染顺序是
   permission → Plan → left → 模型选择器，所以 chip 落在「只读」之后、模型选择器之前，会话
   身份由槽位作为标准 prop 交进来。几何全部取自 DSH 相邻控件（模型/权限 trigger：28px、
   `0 4px 0 8px`、`--dsw-radius-sm`、13/20/400、hover `interactive-bg-hover`、12px caption
   chevron），窄容器折叠照 PermissionSelect 的 `@container (max-width: 460px)`。
10. **弹层是 DSH 的 `Menu`（portal）**：链行用它的子菜单（"跟随默认链" + 每条链一行），焦点、
    Escape、外部点击、定位、层栈都来自原语。**写失败不关闭弹层**，在弹层里显示宿主原样抛出
    的错误；**成功才刷新 chip 并关闭**。没有持久存储时（`persistent: false`）弹层里明说
    "重启后失效"。
11. **探针与连通性覆盖所有链**：`configuredRouteList` 把各链候选摊平后按渠道去重——一张健康
    行说的是渠道，不是链。

## Alternatives considered

1. **严格照原计划：第 2 步只打通读写，切换生效的验收推迟到第 3 步。**
   - 最强的理由：第 2 步的改动面小得多，不必同批改配置形状、设置面板与测试夹具。
   - 为何被否：那样 chip 写进去的选择没有消费者，"真的换了候选"这条承诺被留到未来，而中间
     那一版会让用户以为选链生效了。用户明确选了"把形状提到第 2 步"。
2. **保留 `chain` 当默认链，另加 `chains[]` 存"其它"链。**
   - 最强的理由：设置面板零改动、迁移成本最低，旧配置不需要转换。
   - 为何被否：同一条链会有两种表示（顶层对象 vs 数组元素），默认链与命名链的编辑路径必然
     分叉，而分叉的第一天就看不出"这两份是不是同一件事"。用户要的就是 `chains[]` +
     `defaultChainId` 的统一形状。
3. **给配置加一个显式的形状版本号（如 `chainsVersion: 1`）。**
   - 最强的理由：新形状"写没写过"变成可观测事实，不依赖 schemastery 对 array 的默认值行为。
   - 为何被否：为一个可推导的事实加字段，且这个字段本身要在每次保存时维护、在迁移时必须先
     写对——多一条会漂移的状态。空列表在编辑器里不可达，用"非空"判断足够。
4. **弹层自建 body portal（按设计稿自由排版链行与数字输入）。**
   - 最强的理由：布局完全自由；第 3 步的重试行是输入框，塞进菜单看起来不自然。
   - 为何被否：Menu 原语已经实现了焦点进入/归还、Escape、外部点击、锚点跟随与层栈
     （z-index 1100 那套），自建等于重写并再养一份 z-index 名单。第 3 步的输入行可以作为
     `children` 放进同一个弹层，不需要第二套 portal。
5. **写入时允许未知链 id，读取时再回退。**
   - 最强的理由：写入路径简单，宿主不必读配置。
   - 为何被否：会存下一个永不生效的选择，用户看到 chip 显示"写代码"而路由走的是默认链——
     正是第 5 条 notice 想避免的那种"看着生效了"。

## Consequences

- 收益：每个会话可以有自己的降级顺序，没有绑定的会话行为与之前完全一样；配置里只有一种链
  形状，首次保存后旧键被移除。
- 收益：chip 的失败路径被钉住——写失败弹层不关、chip 不刷新、错误原样上屏；本地 7 条用例
  覆盖注册面、读回、成功/失败、跟随默认、保留重试覆盖与无存储提示。
- 收益：结构规则、探针与健康视图都按"所有链"工作，不会出现"只检查了默认链"的半个真相。
- 代价：设置面板这一版只能编辑默认链。别的链只能靠手改配置创建，重命名/增删要等第 3 步的
  链管理界面——所以这一步是提交单元，不是一个可单独发布的版本。
- 代价："空 `chains` 列表按旧形状读"是一条推断，而不是一条可观测事实。它写在
  `effectiveChains` 的 docstring 里，并且只有在有人手写 `chains: []` 又同时留着旧 `chain`
  时才会产生可讨论的行为差异。
- 代价：每条链拥有完整的一套 `switchOn`/预算/粘滞窗口，复制一条链要重配；本批不引入"链继承"。
- 代价（测试面）：`tests/run.mjs` 的 overlay 生成器要同时支持两种形状；浏览器的保存从 3 个
  配置 op 变成 5 个（含 `unset`），测试夹具的 `applyOps` 必须能应用 `unset`，否则保存一条都
  落不了地。
- 未做：设计文档里"熔断规则属于链"仍未实施——熔断规则与状态都还是全局的（状态全局是本项目
  既有语义；规则的归属是另一个决定）。第 3 步仍要补：弹层里的每路由重试覆盖行、链管理界面。
