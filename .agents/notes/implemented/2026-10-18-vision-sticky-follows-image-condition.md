# Agent Note: 识图粘滞归入图片条件，配置状态色不再借用健康绿

Status: implemented

## Problem

两件事各自独立，但都是"界面把两种不同的东西画成了同一种"。

**其一，`stickyTurns` 站在错误的邻居旁边。** 它是识图路由的后续语义——带图轮之后，还有几轮无图请求继续按"有图"路由。此前它渲染在 `policies` 页签的预算网格里，紧挨着"单请求最多总尝试次数"，而真正决定它有没有意义的图片三态（不限 / 仅带图 / 仅无图）在另一个页签、另一层折叠面板里。用户站在图片条件旁边，看不到这个数；站在这个数旁边，不知道它跟图片有关。更糟的是，`imagesMode` 为 `any` 或 `forbid` 时这个数永远不会被运行时读到，摆在预算网格里没有任何提示，设了也像没生效。

**其二，活动徽标借用了健康色。** 页头卡的"接管中"、默认池的"已启用"、侧栏默认池条目，三处都写死 `healthToneBadge('healthy')`。但 `--dsh-router-tone-ok` 在这套面板里有一个明确且唯一的意思：渠道健康。同一个绿色同时表示"这条规则正在生效"和"这条渠道正常"，在健康工作台与规则视图之间来回切换时，两种语义互相污染。`[2026-10-16 语义色单源笔记](2026-10-16-single-surface-dialog-and-tone-system.md)` 已经确立了"语义色单源、颜色只进点和边"的纪律，这三处是漏网的借用。

顺带两处小问题：候选数词条 `'{n} 候选'` 在 Profile 视图传的是 `candidates.length - 1`（扣掉钉死的 primary），在默认池视图传的是全长，同一个词条一个减一一个不减，页面上没有任何地方解释这个减一；页头卡与子 Tab 栏之间 `gap: 16` 加 `marginBottom: 16`，两块同层级信息被撑成两段互不相关的内容，滚动区晚 30px 才开始。

## Decision

识图粘滞是图片条件的后续，跟着图片条件走；配置状态用 accent，绿色只留给渠道健康。

准入门槛（可机械判定）：

1. **位置跟随语义**：`stickyTurns` 的输入框渲染在 `needImages` 卡片内，且只在 `imagesMode === 'require'` 时出现。判定：`grep stickyTurns` 在 `src/client/` 里不再出现于 `BudgetRow`，`chain.ts` 的 policies 分支不传它；`pipeline.ts` 的 `needImages` 卡片内有 `imagesMode === 'require'` 门。
2. **颜色不跨语义**：配置状态一律用 `S.workspaceStatePill`（accent 文字 + 10% accent 底 + 22% accent 边）。判定：`chain.ts` 不再导入 `healthToneBadge`；健康状态（侧栏"全部正常"、节点 `HealthSignalDot`、渠道卡状态药丸）继续走 `healthTone*` 三函数，不受影响。
3. **词条含义单一**：`candidateCountTag` 只表示"备用数"，两个视图共用。判定：中英两个词条分别为 `{n} 条备用` / `{n} fallback candidates`；计数口径各自不同但含义一致。
4. **同层级靠拢**：页头卡与子 Tab 栏之间 `gap: 10`、`marginBottom: 10`。

## Alternatives considered

1. **三种图片态都显示 `stickyTurns`，加一句说明**
   - 最强的理由：发现性最好。用户在"不限"态下就能看到这个参数存在，知道插件支持粘滞，不用先想到去切"仅带图"才发现它。
   - 为何被否：`any` 与 `forbid` 态下这个数在运行时是死值，一个永远不生效的输入框配一句"这样配置不生效"的说明，正是我们一直在删的那类东西——界面显示一个能力，实际不提供。发现性应该由 P0-2 的页头徽标承担，不是靠摆一个死控件。

2. **`stickyTurns` 仍留在预算网格，改成加一行"仅与「仅带图」相关"**
   - 最强的理由：改动最小，一行 hint 就能澄清语义，不动控件树。
   - 为何被否：位置是它的主要问题。hint 能解释"它是什么意思"，解释不了"为什么它在重试次数旁边"。用户要改图片行为时的视线不会落到预算网格。

3. **Profile 用"条备用"、默认池用独立的"{n} 个候选"键**
   - 最强的理由：默认池没有 primary，全部候选确实都是池成员，用"候选"更准确，也不该被"备用"这个词误导成"有一主多备"的结构。
   - 为何被否：要多一个字典键和一处调用分叉，而两个视图的读者是同一个人、在同一个面板里。词条含义统一成"备用数"之后，Profile 的减一晃了一眼就懂（有 primary，所以备用少一条），默认池全长也懂（没有 primary，全是备用）。分叉换来的是更精确的措辞，代价是又多一处"同一件事两套表达"。

4. **活动徽标改成中性灰，不用 accent**
   - 最强的理由：中性色最保守，不会和 brand accent 抢注意力，也不会被误读成某种状态。
   - 为何被否：accent 在这套面板里已经是"插件自己的、可操作的东西"的颜色（侧栏新建按钮、策略汇总、锁定徽标），用来标示"这条规则是激活的那个"是它的既有语义。"接管中"需要一点存在感——中性灰会和旁边的 provider 徽标、候选数徽标糊在一起。走 `workspaceStatePill` 里 `color-mix` 的 10%/22% 低透明度，也保持了"颜色只进点和边、文字走 tone 变量"的既有纪律。

## Consequences

- 收益：`stickyTurns` 只出现在它真的会生效的地方，站的位置直接说明它归谁管；绿色在面板里恢复单一含义，规则视图与健康视图之间的语义污染消失；`candidateCountTag` 不再是一个减一一个不减的含糊词；页头到控件列表少 20px 空档。改的是三个渲染层文件（`pipeline.ts`、`chain.ts`、`styles.ts`）加两个字典，控制器与数据流一行未动。
- 代价：粘滞设置在 `any` / `forbid` 态下完全不可见，不知道插件支持粘滞的用户在切换到「仅带图」之前不会发现它——这个缺口现在记在 `ui-review.md` 的 P0-2（识图路由需要页头级可见信号）名下，未闭环前它是一个已知的发现性损失。另外 `workspaceStatePill` 与既有的 `primaryLockedBadge`、`needStatusBadgeActive` 在视觉上同源（都是 accent 低透明底），三种徽标现在外观相近，区分靠文字而非颜色。
