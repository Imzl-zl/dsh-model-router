# 可用率不是一个率：窗口权重多乘了一个桶内计数（2026-10-19）

## Context

用户看健康大盘时发现"正常 · 可用率 3578%"，只说了四个字："可用率这对吗？你不注意细节啊？"

他是对的，而且这不是显示格式问题——**这是个率，却能被算成 6000%**。

## Decision

**窗口成功率收编成 `timeline.ts` 一个函数 `windowSuccessRate(bars)`，删掉两处内联算法。**

根因一句话：`weighted += (bar.healthy + bar.degraded / 2) * bar.count`。`bar.healthy`
**本身就是桶内计数**，再乘一次 `bar.count` 就是平方。桶里 1 次观测时 `1×1=1`，看
不出来；桶里 10 次就是 `10×10/10 = 10` → 1000%；用户那种有真实流量的渠道直接
印出 3578%。

同一段错公式在**两处**各写一遍：

- `client/workspace.ts`（渠道卡片徽标"· 可用率 N%"）
- `client/health-ui.ts`（大盘表头"近 4h N%"）

所以用户截图里两个位置显示同一个错数——不是巧合，是同一份代码被抄了两遍。

**为何是收编而不是各改各的**：这两处的窗口、桶长、权重必须一致（否则"柱子全绿、
旁边写 62%"），而它们已经漂过一次（`mergeHealthRecord` 的裁剪规则曾与 host 不
同）。一个率一个算法，是唯一能防止它们再次各算一套的形状。

## Alternatives considered

### A1. 只把两处的 `* bar.count` 删掉，公式留在原处

**最强理由**：两行删除，最小 diff，测试照样过。

**为何被否**：错的不是一个字符，是"同一段业务逻辑存在两份"。这次两份错得一样，
下次一份改一份不改就会漂——而这个项目已经因为"两处各算一套"修过一次（时间线裁
剪规则）。收编进 `timeline.ts` 与 `bucketTimeline`/`pruneTimeline` 并列，那本来
就是窗口规则的家里。

### A2. 顺手把"降级计半次"的权重也改掉（改成计 1 或计 0）

**最强理由**：权重是产品口味，可以讨论。

**为何被否**：用户说的是 3578%，不是权重。限流计半次是有理由的既定决策（一次 429
不该把好渠道涂红），改它会把一个明确的 bug 修成两个待决问题。不动。

### A3. 在 UI 层 `Math.min(100, rate)` 兜一下

**最强理由**：一行，保证再也不出现 >100%。

**为何被否**：那是把症状按下去：100% 的柱子旁边写着被夹掉的 6000%，用户看到的
是一个"永远健康"的谎。率必须在算出来的地方就是对的。

## Consequences

**收益**

- 可用率回到 [0,1]：全部成功 = 100%，一半限流 = 75%，全失败 = 0%，无观测 = —。
- 一个率一个算法；两处 UI 不可能再给出两个数。
- 新增三层回归：纯函数两条（含一个 343 种桶负载组合的不变量枚举）、显示层一条
  （真实构建产物 + 60 个观测挤一个桶，断言渲染出来的每个百分比 ≤ 100）。

**代价**

- 无行为回退：旧数本来就是错的，没有"用户看习惯了"要照顾。
- `windowSuccessRate` 返回 `null`（无观测）而不是 0，两个调用点都要分叉——这是
  原来的语义，保留。

## 验证

- **先用探针复现**（`spike/availability-rate-probe.mjs`，跑真实 `bucketTimeline`）：
  50 次观测挤同几个桶 → **964%**；200 次同刻同状态 → **20000%**；600 次挤一桶 →
  **60000%**。确认是数据形状触发的，不是偶发。
- **单元**：unit **144**（新增两条）；**client-controller 50**（新增显示层一条）。
- **抽样验证**（把公式改回错的再跑）：三条新用例同时转红，显示层那条精确报出
  `got 6000%`；恢复即全绿。证明测试网不是空的。
- remote 15、run.mjs 23 场景 0 失败、bundle / tsc / `node --check` 全过；DSH
  checkout 0 行。
- **为什么隔离浏览器实测没抓到**：那次只发了一轮对话，每个 10 分钟桶里只有 1 次
  观测，`1×1=1` 恰好等于正确值。**这个 bug 只在有真实流量的桶里现形**——用户有
  流量，所以只有他看得到。已按这条写显示层回归，不再依赖"我这边刚好有一次调用"。
