# Agent Note: 删除「会话路由」设置页签

Status: implemented

## Context

2026-10-21 用户在第一次上手时问过「我不应该选择会话吗」，于是链路页加了一个「会话路由」
页签：列出会话 × 各自的绑定，支持逐会话改链、改重试、清理被删会话的孤儿绑定（决策记录
已归档到 `archived/2026-10-21-session-list-in-the-settings-panel.md`）。

一天后同一用户的实际使用反馈是相反的：会话用完就结束，不会长期挂着；真正要选链时人就在
composer 里，chip 是自然的入口。设置页那个列表既显示不出多少有用信息（没标题时只剩 id 末
8 位），又要维护一套「会话清单 × 绑定」的拼接，属于事后总览而不是决策面。

这不是“再修一下列表”的问题：入口本身与使用时机错位。留着它，用户仍然不会点，却要继续
承担它的读口、状态、样式和测试。

## Decision

1. **删除「会话路由」页签**（`src/client/sessions.ts`、页面视图、控制器状态与动作、样式、
   字典键、组件测试）。页面只留「降级链路」与「渠道健康」两个视图。
2. **保留按会话绑定本身**：侧车的 `{ chain, retries }`、chip 的读写、请求时的
   `chainForSession` 都不变；日常选链只在 composer 的 chip 里。
3. **删除只为该页签存在的两个 Remote**：`sessionBindings()` 与 `deleteSessionBinding()`。
   它们是“列出/清理”的读口，没有第二个消费者；保留等于给已删除的 UI 留后台 API。
4. **不新增替代入口**：不做“批量改会话”“孤儿绑定清理”页；被删会话的绑定留在侧车里，
   体量小且不影响路由（读不到该会话就不会被使用）。

## Alternatives considered

1. **保留页签，但只列有绑定的会话并自动补齐标题。**
   - 最强的理由：仍然给“批量看/批量改”留一个地方。
   - 为何被否：用户不使用这个时机；标题缺失只是表象，入口本身不与“正在做的会话”对齐。
     改成只列有绑定的行也只是把一个没人点的页面做小一点。
2. **删 UI、保留两个 Remote 供未来或第三方使用。**
   - 最强的理由：以后想加别的管理面时不用重新加 API。
   - 为何被否：没有消费者的公开 API 是死代码，还要继续维护 codec/校验与测试；未来需要时
     再加是一次明确的决定，而不是现在留一个“也许有用”的口子。
3. **在 chip 里加“批量/其他会话”入口。**
   - 最强的理由：入口跟着使用时机走。
   - 为何被否：chip 是“本会话”的控件，塞跨会话管理会把一个 28px 控件变成导航入口；用户
     要的只是当前会话。

## Consequences

- 收益：少一个视图、一套状态、两个 Remote 与约一百行会话拼接逻辑；页面只剩“配置链”和
  “看健康”两件事。
- 收益：不再需要 `session.list` + title 投影 + `sessionBindings` 的三方拼接，也不会出现
  “标题读不到只剩 id”的半成品列表。
- 代价：被删会话留在侧车里的绑定没有 UI 清理入口。它们不会被路由读取（会话 id 不再出现），
  只是文件里多几行；如果以后真的成为体量问题，应该在写入侧做懒清理，而不是恢复一个页面。
- 代价：删除 `sessionBindings` / `deleteSessionBinding` 是对外部 Remote surface 的移除；
  本项目仍在 `0.x`，没有第三方消费者，按“删死代码”处理。
- 未做：不做会话归档/批量配置；不做绑定的自动回收。
