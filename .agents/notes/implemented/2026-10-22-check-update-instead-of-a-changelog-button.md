# Agent Note: 右上角改成「检查更新」，版本与它改了什么一起给

Status: implemented

## Problem

工作台右上角原来是一个「更新日志」按钮：点开只是把**当前安装版本**的 CHANGELOG 再摊
一遍——那段文字在升级后本来就会自动弹一次，按钮第二次打开得到的是同一个东西。用户原话
是"很鸡肋"。真正缺的是另一半：**有没有更新的版本**。版本号与它改了什么本来就是同一个
问题，拆成两处则两处都不完整（只有版本号时，用户不知道该不该更新；只有说明时，用户不
知道自己有没有）。

DSH Market 自己有检查更新与更新说明，但那是它插件内部的 UI 状态（它的 client bundle 里
`updateNotes` 只是组件 state），没有给别的插件调用的服务面；本插件也不能假设用户装了它。

## Decision

一个按钮、一个弹窗，先回答"有没有新版本"，再回答"新版本改了什么"。

准入门槛（可机械判定）：

1. **版本以 registry 为准**：`https://registry.npmjs.org/dsh-models-router/latest` 的
   `version` 是"最新已发布"的唯一答案（用户装的就是 registry 上的东西，不是 GitHub 最新
   tag）。不是合法 semver 的值不算版本。
2. **新版本的说明取自它自己的 release body**：CI 用 `scripts/release-notes.mjs` 把
   CHANGELOG 的那一节写进 GitHub Release，所以 `v<latest>` 的 body 与下一个产物内嵌的
   说明是同一段文字。
3. **当前版本的说明不联网**：它内嵌在产物里（`src/release.generated.ts`），离线也读得到，
   且永远不会与已安装的版本不一致。
4. **失败分成两种，各自说话**：registry 读不到 = "版本问题没有答案"（`error`，绝不显示
   "已是最新"）；版本读到了但 release 读不到 = 版本答案仍成立（`notesError`）。
5. **检查在宿主半包执行**：浏览器不自己连第三方（与连通性检查搬到宿主同一条理由）；新增
   `@Remote checkUpdate()` 挂在插件既有的 Host face 上。
6. **每次注入的样式表必须自洽**：整张 CSS 的注释成对、花括号配平（`client-controller.mjs`
   的源级守卫）。少了 `*/` 会把后面所有规则吞成注释——本轮实测踩到过，浏览器不报错，
   只是"少了几条样式"。

## Alternatives considered

1. 浏览器半包直接 fetch registry 与 GitHub
   - 最强的理由：不用碰宿主与 Remote，也不用重新生成 typert 产物；浏览器还会自动走系统
     代理（本项目实测过 Node 直连被 TLS 重置、浏览器因系统代理正常的渠道）。
   - 为何被否：本插件的网络 I/O 一直在宿主（连通性检查就是为了错误码不被 wrapper 吃掉而
     从浏览器搬到宿主的）。再把一条第三方连接放回渲染进程，等于给"谁能连谁"开第二个口子，
     而且 CSP 或代理差异会让同一份代码在不同壳里表现不一致。
2. 复用 DSH Market 的检查结果
   - 最强的理由：它已经在做这件事，命中率高，用户装完就有；我们一行都不用写。
   - 为何被否：那是它的组件内部状态，没有跨插件服务面；把它当契约用，等于依赖一个第三方
     插件的私有实现，而本插件是独立发布的 npm 包（用户可能根本没装 Market）。
3. 保留「更新日志」按钮，另加一个「检查更新」
   - 最强的理由：不改变现有入口，保守。
   - 为何被否：两个按钮回答同一个问题的两半，用户还得知道该点哪个；升级后自动弹的那次
     说明已经覆盖了"我这一版改了什么"，常驻入口只该负责"要不要更新"。
4. 检查失败时也显示"已是最新"
   - 最强的理由：界面上永远有结论，没有悬空状态。
   - 为何被否：那是在没有答案时编一个答案——用户会因此不去更新。失败就写失败，旁边仍然
     给当前版本的说明。

## Consequences

- 收益：一个入口同时给出"最新版本 + 有没有更新 + 新版本说明 + 发布页"；已是最新时仍能读
  当前版本的说明（离线可用）；检查失败与"已是最新"在屏幕上彻底分开。
- 代价：点这个按钮会真的发两次外部请求（registry + GitHub release），且只在宿主能连通
  时才成立；`ui.update*` 三个状态是新的视图状态，`checkUpdate` 成为 Host face 的第六个
  方法（Remote 的方法清单与产物在 `tests/remote.mjs` 里被钉住，加方法必须一起改）。
- 未做：弹窗里没有"一键更新"按钮——安装动作在 DSH 的插件页（Market 管的），本插件只给
  发布页链接与一句指路。
