# Agent Note: 会话重试覆盖的输入行与链管理

Status: implemented

## Context

第 1 步让宿主能存 `{ chain, retries }`，第 2 步让会话能选链。到这一步为止，用户能看见的只有
"选哪条链"：每路由的重试次数还得手改存储，链本身也只能手写 YAML。用户第 3 步要的是：
弹层里每个候选一行数字输入（**空 = 跟随链，0 = 不重试**，别把两者混起来），以及设置面板里的
链管理。

三条硬约束：

- `0..9` 是**宿主**的边界（`bindings.ts` 的 `assertBinding`），wire schema 只有形状；
- `0` 与"没填"必须分开——宿主侧由 `resolveChain` 的 `??` 保证，界面上也必须看得出来；
- 弹层是 DSH 的 `Menu`（portal）。输入行不能自建第二层浮层，否则焦点/Escape/外部点击各一套。

## Decision

1. **重试行只列本会话会走的那条链的候选**：给一条用不上的路由配次数，只会写进一个永远不
   生效的键。
2. **提交时机是失焦或回车**，不是每次按键。一次按键一次写会把存储写穿；而且输入 "1" → "10"
   的中间态会被存下来，而 10 是越界值、会被宿主拒绝弹错。
3. **空 = 删键（跟随链）；0..9 = 覆盖**。越界值不夹、不猜：原地报错并保留用户输入，让他自己
   改。错误文案里的上限来自 `MAX_SESSION_RETRIES`——与宿主同一个常量，不另写一个 9。
4. **写失败保留输入 + 错误行，弹层不关**：与换链同一条契约（成功才刷新），失败时 chip 不能
   显示一个没落库的数字。
5. **链管理放链路页第一个分区**：它决定下面五个分区编辑的是哪一条，放最后会让表单悄悄换目标。
   行 = 编辑/编辑中 + 名称输入 + 默认徽标或「设为默认」+「删除」。
6. **编辑目标**：没显式选过链时跟随默认链（"设为默认"之后编辑目标一起走）；点过「编辑」之后
   跟选择走，不跟默认走。
7. **最后一条链不能删**（没有链 = 插件完全不接管，那不是点删除时想要的结果）；删默认链时默认
   移交剩下的第一条；`id` 不可编辑，改名只改 `name`。
8. **新增链给空候选**，不复制默认链。
9. 保存写 `chains` + `defaultChainId`，并 `unset` 旧的 `chain` 键（存储里只剩一种形状）。

## Alternatives considered

1. **每次按键都写（onChange → setSessionBinding）。**
   - 最强的理由：不用失焦提交，界面永远等于存储，也不会有"输入了但还没生效"的中间态。
   - 为何被否：一个数字敲两下就是两次落盘；而且 "1" → "10" 的中间态会被写进去，10 是越界值，
     宿主拒绝后用户会看到自己没按过的一次错误。
2. **在弹层外再开一个 Modal 编辑重试。**
   - 最强的理由：输入空间大、能放完整说明，也不必挤进 274px 宽的菜单卡。
   - 为何被否：用户改的是"这一轮打到哪"，与选链是同一件事；两个浮层会让"关掉一个还剩另一个"
     变成新的状态机，而弹层本来就已经有焦点/关闭契约。
3. **把重试行做成 `Menu` 的数据行（`items`）。**
   - 最强的理由：复用菜单的键盘行走与选中语义，代码最少。
   - 为何被否：数据行是 `menuitem` 按钮，塞输入框进去会让 Enter/Tab 的含义与"选择一行"冲突；
     `children` 允许任意组件、仍共享同一个弹层与关闭行为。
4. **新增链时复制默认链。**
   - 最强的理由：用户多半只改一两处，复制省事，也避免新链"不可用"。
   - 为何被否：复制让"两条链完全一样"成为默认状态，改一半就留下一条永远重复的链；空候选让
     "这条链还没配"变成可见事实。
5. **把"设为默认"和"编辑目标"绑成一件事。**
   - 最强的理由：少一个概念——用户在看的那条就是默认那条。
   - 为何被否：默认是"没绑定的会话走哪条"，编辑目标是"我在看哪条"，两者合法地可以不同
     （临时看一眼别的链的配置）。绑定之后"设为默认"会顺带把页面跳走，读起来像误触。

## Consequences

- 收益：会话级重试覆盖可设、可清、可读回，且 `0` 与空在界面上是两种状态（0 显示 0，空显示
  占位「跟随」）；重启后仍在（实测：写入 `storages/model_router_sessions.json`，刷新后输入框
  回显 5）。
- 收益：链可以增删改名而不用手改 YAML；`id` 稳定意味着改名不动任何会话绑定。
- 代价：链没有候选时重试区块不渲染——用户看到的只有链行，可能被读成"重试不能按会话设"。
  这是刻意的（没有路由就没有可配的次数），但需要时可以在空态加一行说明。
- 代价：越界值要等失焦/回车才报错；输入着 10 的时候界面不会立刻变红。
- 代价：隔离 home 里"保存"必然失败——插件行是 `--patch` 插入的，settings 找不到该行
  （tools.md 已记根因）。所以链管理的**落盘**只能在真安装里验；本轮的浏览器实测到"草稿正确 +
  失败提示正确"，落盘由 client-controller 的 save op 断言（`chains`/`defaultChainId`/`unset
  chain`）与宿主 schema 兜住。
- 代价：重试行的"有效次数"只在 title 里（"留空则跟随链：N 次重试"），没有内联数字——避免把
  跟随值显示得像已填值。
- 未做：熔断规则按链（规则与状态都还是全局的）。
