# docs 文档标准

## 结构

- `architecture.md` 是当前设计总入口；详细实现模型放在 `design/`，第三方资料放在 `references/`。
- 事实、方案和待决决定须明确标识，不以一个页面兼任源码 API 清单或实现手册。
- 一项设计事实只保留一个权威说明；其他页面用链接引用。

## 去废话守则

1. 只记当下事实；不写「以前 / 现在 / 不再 / 改名为」等变迁叙述。
2. 不人肉抄写能由源码或 AST 生成的 API/配置清单；文档只定位相关代码。
3. 文档代码块须真实可编译或运行；未验证的概念示例须标注伪代码或草案。
4. 字数超限依次下沉迁移、精简浓缩、申请提额；不得删减约束凑数。

## 来源与状态

- DSH 源码引用标明仓库相对路径与核对行号；使用指向只读 checkout 的可点击 `file:///` 链接。
- 提案写成提案，用户决策标明待确认；不把建议默认值写成 DSH 已实现行为。
- 第三方产品事实链接至对应官方原始文档；来源有变化时重新核验。
